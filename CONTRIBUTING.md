# Contributing to NetZero Labs

Thank you for helping build a trustworthy directory of open climate and environmental AI.

You can contribute by:

- proposing a new project;
- correcting a technical or licensing detail;
- reporting a broken or moved resource;
- adding a paper, model card, dataset, or evaluation;
- improving the English or Vietnamese documentation.

## Project eligibility

A project should have a clear connection to climate science, environmental analysis, energy transition, sustainability, climate policy, or an enabling task designed specifically for those domains.

Strong candidates usually provide several of the following:

- public source code;
- downloadable model weights or datasets;
- a clear license for each released artifact;
- reproducible setup and inference instructions;
- documented training or retrieval data;
- model cards, data cards, evaluation results, or a research paper;
- limitations, safety considerations, and intended uses;
- source attribution or passage-level citations for RAG systems.

## Openness classification

NetZero Labs describes the actual availability of each project:

| Status | Review standard |
|---|---|
| **Open** | Core code and relevant artifacts have clear licenses that permit reuse and modification. |
| **Open pipeline** | The retrieval, data, or application pipeline is public, but an important runtime component is hosted or proprietary. |
| **Source-available** | Code or weights are public under custom, non-commercial, or otherwise restrictive terms. |
| **Mixed** | Artifact terms differ, or an important repository does not declare a license. |

A public GitHub repository without a license does not automatically grant permission to reuse its code. A downloadable model may also inherit restrictions from its base model.

## Before submitting

Please check that:

1. Every link is public and resolves to the intended resource.
2. The project description is supported by its own documentation or paper.
3. Code, model, and dataset licenses are listed separately where they differ.
4. Model sizes, training data figures, and benchmark claims have a primary source.
5. Any proprietary API, hosted dependency, or commercial restriction is disclosed.
6. The project is not presented as endorsed by IPCC or another institution unless an official source confirms that relationship.

## Submission process

Use the [project submission form](https://github.com/netzerolabs/netzerolabs/issues/new?template=project-submission.yml).

Maintainers will:

1. confirm climate or environmental relevance;
2. inspect the linked artifacts and documentation;
3. verify the declared licenses;
4. assign an openness category;
5. rewrite promotional claims as neutral, evidence-based descriptions;
6. request clarification when an important detail cannot be verified.

Submission does not guarantee inclusion. Projects may be omitted when their public artifacts, licensing, relevance, or technical claims cannot be verified.

## Corrections and updates

Open an issue with:

- the current statement;
- the proposed correction;
- a primary source supporting the change;
- the date you verified it.

License changes and removed model weights should be reported promptly because they can change a project's classification.

## Style

- Use concise, factual language.
- Link to primary sources whenever possible.
- Distinguish code, data, weights, papers, and demos.
- Avoid “fully open,” “state of the art,” or similar claims without precise evidence.
- English and Vietnamese contributions are both welcome.

## Conduct

Be respectful, evidence-led, and constructive. Discuss projects and claims rather than people. Do not include credentials, private data, copyrighted report copies, or other material you are not authorized to share.
